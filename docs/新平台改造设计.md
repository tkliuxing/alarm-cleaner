## 1. 背景与目标

旧平台是 ASP.NET MVC（EasyUI）页面，本工具（`main.py` / `gui.py`）通过模拟表单请求实现三类自动处理：

| 旧工具功能 | 旧接口 |
| --- | --- |
| 类型1·报警处理 | `POST /TopGps/Report/AlarmProcessQuery/Search` + `AlarmEXProc` |
| 类型2·安全报警 | `POST /CGO8/SafeAnly/SafeAlarmProRpt/Search` + `AlarmPro` |
| 查岗 | `POST /TopGps/Report/PlatformQuery/Search` + `SupplyReply`（算术应答） |

平台现已整体升级为 **Vue 3 SPA（vue-pure-admin 体系）+ REST API 网关**，产品名 `Cgo8 Pro 车辆主动安全智能防控平台 v4.5.0`。旧的 `/CGO8`、`/TopGps` 页面接口在新服务器上不再适用，需要按新接口重写本地逻辑。

**目标**：在保持工具原有交互（CLI + tkinter GUI、定时轮询、"今天 00:00 ~ 当前时刻" 批量补处理）的前提下，重写底层 HTTP 逻辑以适配新平台。**菜单名称沿用新平台一致命名**（见 §4）。

## 2. 新平台技术架构概览

```
浏览器 (Vue SPA, hash 路由 /#/...)
   │  axios，统一 baseURL = /api
   ▼
/api 网关  ──►  ims 服务  (/api/ims/**)     鉴权、菜单、组织、车辆、报警处理、轨迹
           └►  fcdata 服务 (/api/fcdata/**)  通用表单/字典/报表引擎（异步报表）
WebSocket (端口 9087, /ws)  ──►  实时车辆状态 / 实时报警推送
```

要点：

1. **统一网关前缀 `/api`**，所有业务接口形如 `POST /api/<service>/<module>/<action>?lang=zh-CN`。
2. **鉴权 = JWT Bearer Token**（RS256）。登录返回 `accessToken` + `refreshToken`，前端存于 `sessionStorage`。
3. **请求体 / 响应体加密能力存在但本服务器未启用**：前端含 `cryptoService`（AES-256-CBC + RSA 包裹 AES Key），但实测本服务器登录响应为明文 JSON、业务请求体为明文。只有**登录密码字段**做了 RSA 加密（见 §3）。
4. **报表数据走"异步报表引擎"**：提交查询任务拿 `taskId` → 轮询 `result` 取 `dataList`（§5）。旧平台"一次 Search 拿一页"被改成"提交任务 + 轮询"。
5. **实时报警走 WebSocket**（非 HTTP）。但"补处理历史报警"这一核心场景走的是异步报表引擎，**不依赖 WebSocket**，可纯 HTTP 实现（这点对本工具至关重要）。

### 关键全局信息（`sessionStorage`）

- `authorized-token` = `{ accessToken, refreshToken, expires, userId }`
- `user-info` = `{ userId, userType, username, orgId, userCode, userLevel, tokenFlag, refreshToken, expires }`
  - 实测：`userId=99997769`、`orgId=8855726`、`userCode=江林`、`userType=1`

## 3. 鉴权与登录流程

### 3.1 获取公钥
```
GET /api/ims/user/getPublicKey
→ { rspCode:0, data:{ publicKey:"<base64 DER body>", encrypted:<bool>, algorithm:"AES-256-CBC" } }
```
`publicKey` 是不含 PEM 头尾的 base64；前端拼成 `-----BEGIN PUBLIC KEY-----\n{body}\n-----END PUBLIC KEY-----` 后用 `JSEncrypt`（RSA/PKCS#1 v1.5）加密。

### 3.2 登录
```
POST /api/ims/user/login?lang=zh-CN
Content-Type: application/json
Body:
{
  "userCode": "江林",
  "password": "<RSA(明文密码) 的 base64，256 字节 ⇒ RSA-2048>",
  "userType": 1,        // 企业用户=1（个人用户为另一值）
  "loginMode": 1
}
→ { rspCode:0, msg:"操作成功",
    data:{ userId, userType, accessToken, refreshToken } }
```

实测要点：
- 登录请求头仅 `Accept / Content-Type / X-Requested-With`，**未带 Bearer**（登录在 TOKEN 白名单内）。
- 密码是用 §3.1 公钥 **直接 RSA 加密明文密码**（JSEncrypt 默认 PKCS#1 v1.5）。
  - ⚠️ 与旧平台不同：旧平台是 `MD5(密码)` 再 RSA；新平台**疑似直接 RSA(明文)**（前端 `encrypt()` 附近无 MD5 调用）。
  - 由于 RSA PKCS#1 v1.5 填充随机、密文不可比对，**实现时需用账号实测**：先试 `RSA(明文)`，若 `rspCode≠0` 再试 `RSA(MD5hex)`。
- RSA 密钥长度为 **2048 位**（旧平台 1024 位）。

### 3.3 鉴权使用
后续所有业务请求带：
```
Authorization: Bearer <accessToken>
```
- TOKEN 白名单（无需带 token）：`/refreshToken`、`/login`、`/ims/user/getCaptcha`、`/ims/user/getPublicKey`、`/ims/user/getSingleLoginData`。
- Token 过期：`POST /api/ims/user/refreshToken`（用 refreshToken 换新 accessToken）。`accessToken` 实测有效期约 2 小时，`refreshToken` 约 3 天。
- 退出：`POST /api/ims/user/logout`。

> 工具内可不用 refresh，沿用旧策略：某轮处理 401/失败时**直接重新登录**（`gui.py` 已有 `relogin` 回调）。

### 5.2 异步报表引擎（报表分析所有报表共用）

**第一步：提交列表查询任务**
```
POST /api/fcdata/asyncRecord/listAsync?lang=zh-CN
Body:
{
  "listId": 664,               // 报表标识：报警处理查询=664
  "configLevel": 2,
  "configUserId": "99997769",  // = 当前 userId
  "current": 1,
  "size": 20,
  "last": 1,
  "parentReq": null,
  "queryConditions": [
    { "fieldType":"date",
      "fieldCode":"fq_76491_222_alarm_begin_time",   // 报警开始时间（报表内字段编码）
      "symbol":"dynamic",
      "value":["2026-06-16 00:00:00","2026-06-16 23:59:59"] },  // 时间窗 [begin,end]
    { "fieldType":"number",
      "fieldCode":"fq_71239_291_duration",            // 持续时长
      "symbol":"greaterequal", "value":"1" },
    { "symbol":"in", "fieldCode":"alarm_flag",         // 报警类型（默认全选）
      "value":[1001,1002,1013,1014,1018, ... ,1354] }
  ]
}
→ { rspCode:0, data:{ taskId:"<uuid>" } }
```

**第二步（可选）：提交总数任务**
```
POST /api/fcdata/asyncRecord/countAsync   （Body 同上）→ data.taskId
```

**第三步：轮询结果**（每 ~400ms 一次，最多 ~300 次）
```
POST /api/fcdata/asyncRecord/result?lang=zh-CN
Body: { "taskId":"<uuid>" }
→ { rspCode:0, data:{
      status: 2,            // 0=TODO 1=DOING 2=DONE 3=CANCEL 7=EXPIRED 8=FAILED 9=NOT_FOUND
      process: 100,
      result:{ dataList:[ {…行…} ], total: N }
  } }
```
- `status===2`（DONE）取 `result.dataList`；`8/3/7/9` 视为失败/结束。
- 取消任务：`POST /api/fcdata/asyncRecord/cancel { taskId }`。

> 报表分析的"导出/统计"另有 `/api/fcdata/asyncReport/listAsync`、`asyncReport/resultBatch`，本工具不需要。

### 5.4 报警处理（核心写接口）— 类型1 与 类型2 共用
来自前端 `alarmHandle-50366504.js`：`r.request("post","/ims/alarm/alarmHandle",{data})`。
```
POST /api/ims/alarm/alarmHandle?lang=zh-CN
Authorization: Bearer <accessToken>
Body:
{
  "alarmBaseDataList": [
    { "alarmId":"26061623...", "alarmType":4, "alarmFlag":4005,
      "vehicleId":"1776442957822406", "alarmBeginTime":"2026-06-16 15:12:09",
      "alarmLevel":2 }
  ],
  "processTime": "2026-06-16 16:00:00",   // YYYY-MM-DD HH:mm:ss
  "userId": 100,                          // 前端固定传 100（后端以 token 为准）
  "processType": 2,                       // 2 = 处理
  "processMode": 9,                       // 处理方式 code（见下表），9=补充处理（旧工具销账行为）
  "processContent": "补充处理",            // 处理说明文本（自由文本）
  "remark": ""
  // 可选: "processResult": <值>
}
→ { rspCode:0, data:… }   // rspCode===0 即成功
```

**`processMode` 取值 = 字典 `dict typeId=19`「报警处理方式」的 code（实测）**：

| code | 含义 | code | 含义 | code | 含义 |
| --- | --- | --- | --- | --- | --- |
| 1 | 发送信息 | 5 | 确认误报 | 13 | 短信通知 |
| **2** | **停止报警** | 8 | 严重人工干涉 | 14 | 拍照 |
| 3 | 电话处理 | **9** | **补充处理** | 15 | 监听 |
| 4 | 确认报警 | 10 | 忽略 | 16 | 语音对讲 |
|   |  | 11 | 其他 | 17 | 确认报警并上传传递单 |
|   |  | 12 | 语音通知 | 18 | 亲情语音播报 |

- ⚠️ 纠正：旧工具的"**补充处理**"对应新 **`processMode = 9`**（不是 1；1 是"发送信息"，会下发终端消息）。补充处理仅生成处理记录销账，**不向终端下发指令**，最贴近旧工具行为，是自动销账的推荐值。
- "**停止报警**"= `processMode = 2`。
- 字典查询：`POST /api/fcdata/dict/list {"typeId":19}` → `dataList:[{code,text,...}]`。
- 支持**批量**：`alarmBaseDataList` 一次传多条（对应 UI"批量处理"按钮）。
- 部分处理方式（发送信息/语音通知等）会额外经 WebSocket `syncSend` 下发终端指令；**补充处理(9)/停止报警(2) 等只调用 `alarmHandle` 即可**，纯销账无需接 WebSocket。

#### ⚠️⚠️ 关键坑：`processContent` 必须是该处理方式下的合法子选项（实测）

抓包对比 UI 真实成功请求发现：**`processContent` 不是自由文本，必须匹配所选 `processMode` 的子选项**，否则服务端**返回 `rspCode:0` 但静默不生效**（报警仍未处理）：

| processMode | 对应 processContent（UI"处理方式"子下拉的值） |
| --- | --- |
| `2` 停止报警 | **`报警解除`** ✅（实测唯一可用值；传字面"停止报警"会静默失败） |
| `9` 补充处理 | `补充处理` |

> 验证：UI 弹窗里选「停止报警」后，下方"处理方式"子下拉默认是「报警解除」，点"立即发送"→ 顶部弹「处理成功」。抓到的请求体 `processMode:2, processContent:"报警解除"`，响应 `{rspCode:0, msg:"操作成功", data:null}`。本地客户端用 `processContent:"停止报警"` 时同样 `rspCode:0` 但报警不消失；改成 `"报警解除"` 后报警从未处理列表消失（确认销账）。
>
> 因此 **`alarmHandle` 成功与否不能靠 `rspCode`/`data` 判断**（成功也是 `data:null`），需重新查询确认 `is_process` 是否翻转。本工具 `processMode=2` 默认配 `processContent="报警解除"`。

### 5.5 类型2·安全报警（主动安全 › 证据中心 › 报警处理查询，listId 738）

与类型1 同引擎、同处理接口、同结果行结构，仅 `listId` 与时间字段编码不同（均已实测）：
```

  "queryConditions":[
    { "fieldType":"date", "fieldCode":"fq_80839_222_alarm_begin_time",
      "symbol":"dynamic", "value":[begin, end] },
    { "symbol":"in", "fieldCode":"fq_6043_291_alarm_flag",
      "value":[3001,3002,...,9001] }   // ADAS 报警类型，可省略=全部

```
- 实测：listId **738**（注意：菜单首屏的"车辆报警信息"实时弹窗用的是 listId 132，做实时销账；按时间窗补处理用日期报表 738）。

- 处理同样走 `POST /api/ims/alarm/alarmHandle`（§5.4）。

#### ⚠️ 重要：664 与 738 是同一批报警的两个过滤视图

实测（同一时间窗、仅按时间过滤）：**664 与 738 返回完全相同的报警集合**（alarm_id 100% 重合）。两个页面的真正区别只是各自报表内置的"报警类型(alarm_flag)"默认范围：

| 报表 | alarm_flag 查询字段（实测） | 默认类型范围 |
| --- | --- | --- |
| 664（类型1·报表分析） | `fq_8544_291_alarm_flag` | 普通报警 `1000..1356`（55 项） |
| 738（类型2·主动安全） | `fq_6043_291_alarm_flag` | ADAS `3001..9001`（37 项） |

664 默认值列表：`[1001,1002,1013,1014,1018,1023,1032,1033,1035,1321,1344,1307,1303,1300,1000,1004,1005,1006,1007,1008,1009,1010,1011,1012,1024,1025,1026,1027,1028,1034,1036,1037,1029,1030,1003,1040,1019,1020,1021,1022,1131,1313,1038,1304,1310,1311,1320,1330,1315,1301,1340,1355,1356,1353,1354]`（另带 `fq_71239_291_duration ≥ 1`）。
738 默认值列表：`[3001,3002,3003,3004,3005,3006,3007,3016,3017,4001,4030,4004,4002,4005,4003,4029,4016,4017,4018,4022,4300,4031,5001,5002,6001,6002,6003,6004,7001,8001,8002,8003,8004,8005,8006,8007,9001]`。

**本工具的处理决策（已与使用方确认）：不加 alarm_flag 过滤，按时间窗全量销账。** 原因：
1. `alarmHandle` 按 `alarm_id` 销账，处理一次即全局生效；只查全量一次即可覆盖"两个页面"所有报警，不会漏、不会重复销账。
2. 实测存在像 `4007「驾驶行为监测功能失效报警」` 这类报警**不在 664、也不在 738 的默认列表**里——若忠实照搬两页过滤反而会漏掉它。全量查询能一并捞出处理。

> 代价：`processors.process_type2` 在数据上与 `process_type1` 重复（类型1 处理后类型2 多为空跑）。保留两者仅为对应 UI 两个入口、并对轮询间隙新产生的报警提供二次兜底。如日后需要"忠实分页"，把上表的 `{fieldCode, symbol:"in", value:[...]}` 条件加进对应 `process_typeN` 即可（注意会漏非默认类型）。

**1) WebSocket 连接**（实测）：
```
ws://******:9087/ws          # 端口取自 sysConfig.wsPort=9087；https 时 wss://<sslIp>:<sslWsPort>/ws
```
- 鉴权：`accessToken` 作为 **WebSocket 子协议**传入，即 `new WebSocket(url, [accessToken])`
  （HTTP 头表现为 `Sec-WebSocket-Protocol: <accessToken>`）。
- 握手顺序：
  1. 连接成功后，**服务端**先推一条配置消息，内含服务端分配的 `clientId`（及各列映射）。
  2. 客户端发送登录帧：`{"action":"login","time":<ms>,"version":1,"orderId":1,"body":{"clientId":<上一步的clientId>}}`
  3. 之后按需发送指令；周期性发送 `{"action":"ping",...}` 心跳。
- `orderId` 按 `action` 自增（每种 action 各自从 1 开始递增）。

**2) 查岗应答帧（`sendCmd`，实测捕获，已拦截未真正发送）**：
```json
{
  "action": "sendCmd", "time": 1781607534747, "version": "1", "orderId": 2,
  "body": {
    "cmdCode": 134812417,                 // 平台查岗应答 的指令码（固定）
    "clientCmdId": "75y392ue1x",          // 客户端随机串（去重用）
    "platformIds": ["24"],                // 取自记录行 ext809_id._value
    "cmdParams": {
      "objectType": 2,                    // = 行 query_type._value（单个业户=2）
      "responder": "(危)包头市江林物流有限责任公司",  // 应答人=当前用户名/企业名
      "responderTel": "",
      "objectId": "999999999",            // = 行 query_id
      "infoId": 1342639,                  // = 行 info_id
      "infoContent": "2",                 // ★ 应答内容 = calc_suanshi(查岗信息内容)
      "type": null,
      "answer": "",
      "userId": "99997769",               // = 当前 userId

```
- 应答内容 `cmdParams.infoContent` 即旧平台 `rspContent`：算术题（`查岗信息内容` 形如 `1+1=`）用 `calc_suanshi()` 求值后填入。
- 字段从 listId 1143 的结果行映射：`reqUniqueId←unique_id, objectId←query_id, objectType←query_type._value, infoId←info_id, reqTime←rece_time(转毫秒), platformIds←[ext809_id._value], responder←当前用户名, userId←userId`。

**3) 实现注意 / 仍需联调**：
- 需要 WS 客户端库（如 `websocket-client`）。`reqTime` 用记录的请求时间毫秒戳；`clientCmdId` 随机生成。
- `clientId` 必须取自连接后服务端首帧，不能臆造。
- 发送后服务端通过 WS 回推应答结果（`rspCode`），需读取确认成功。
- ⚠️ 真实发送会向监管平台回送应答，**联调务必用测试查岗记录**（抓包阶段已用客户端拦截，未真正下发）。

### 6.2 类型1 处理流程（伪代码）
```python
client.login(user_code, password)               # §3
rows = client.query_report(
    list_id=664,
    conditions=[
        {"fieldType":"date","fieldCode":"fq_76491_222_alarm_begin_time",
         "symbol":"dynamic","value":[begin, end]},
        # 可加 is_process 条件只取未处理；或本地过滤
    ],
)
pending = [r for r in rows if r["is_process"]["_value"] == 0]
batch = [{
    "alarmId":  r["alarm_id"],
    "alarmType":r["alarm_type"]["_value"],
    "alarmFlag":r["alarm_flag"]["_value"],
    "vehicleId":r["vehicle_id"]["_value"],
    "alarmBeginTime": r.get("begin_time") or r["fs_80426_222_alarm_begin_time"],
    "alarmLevel": r["alarm_level"]["_value"],
} for r in pending]
client.alarm_handle(batch, process_mode=9, process_content="补充处理")  # 9=补充处理
```

### 6.3 分页
异步引擎用 `current` / `size` 分页（实测默认 size=20）。补处理场景可把 `size` 调大（如 200/500）减少轮询轮次，或循环 `current` 直到取满 `total`。
